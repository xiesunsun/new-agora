# 任务收尾与资源回收

## 开始与关闭任务

开发任务开始时，在实际执行的仓库根目录运行 `pnpm task begin <task-id>`。`task-id` 使用日期和本轮目的，例如 `2026-11-09-save-recovery`。命令记录执行目录、起点、基线和任务身份，不创建分支或 worktree。

`SessionStart` 会打印实际收到的 hook `session_id`。需要自动收尾提示时，用该值建立任务绑定。没有观测到此事件时，任务保持未绑定，使用显式命令完成检查。不能用聊天列表里的 UUID 冒充已观测的 hook session。

准备交付时先运行 `pnpm task close <task-id>` 请求收尾。当前代理回顾本轮操作，核对发生过的失败，再对照 [DeepSeek Harness 的固定来源](decisions/repository-governance.md#deepseek-harness-的依据)。只把有依据、仍会影响后续工作的经验写入所属规则。没有必要增加规则时，记录原因。

复盘 JSON 记录本轮结果、失败及处理、采用或拒绝的经验、实际检查、资源去向和对照来源。当前状态和所需字段由 `pnpm task status <task-id>` 与收尾命令报告。报告写入任务目录，再运行 `pnpm task close <task-id> --reflection /absolute/path/reflection.json`。

检查通过后生成回执。回执绑定最终提交、文件清单摘要、复盘和资源证据。此后修改源码或证据会使旧回执失效，需要重新检查收尾。回执证明程序检查了记录，不替代人对复盘质量的判断。

## Hook 的职责与验收

[项目配置](../.codex/hooks.json)使用 command handler。事件由 [Codex Hooks](https://learn.chatgpt.com/docs/hooks)定义。

| 事件 | Agora 执行的操作 |
| --- | --- |
| `SessionStart` | 报告实际目录、分支、改动和 session，提示待收尾任务及工具限制 |
| `Stop` | 只检查匹配 session 且已请求收尾的任务。记录缺失时最多请求当前代理续跑一次 |
| `PreToolUse` | 按[工具限制](../.codex/tool-policy.json)拒绝已知不可用的连接器创建 PR 操作 |

普通中间回复不启动复盘。`stop_hook_active` 和持久化提示标记防止重复续跑。提示发出后仍未完成的任务保持未完成，不能把提示标记当作回执。代理可以继续显式运行收尾命令。

命令 hook 不调用模型，不读取私有聊天存储，也不自行修改规则。真正的复盘由当前代理完成。`SessionEnd` 无法驱动后续推理，因此不承担这项任务。

任务没有请求收尾时，`Stop` 无法判断开发工作是否已经完成。交付前运行 `close` 是开发协议的一部分。这项限制必须与自动化能力一起说明。

分别记录三个验收结果。

1. 仓库中是否存在正确的配置与脚本。
2. CLI、模拟事件及反例是否通过。
3. 实际 Codex 宿主是否加载、信任并触发该定义。

修改 hook 后，宿主要求对新定义重新审阅信任。旧聊天绑定到另一 worktree 时，也要核对它实际加载的文件。前两项通过不能写成第三项通过。

改 hook 时，先在未加载的候选文件中验证配置。测试实际启动命令，覆盖旧 worktree 缺少新脚本、子目录启动、脚本崩溃与无效输出，再恢复项目配置。启动失败要给出有效 JSON 警告，不能让 `Stop` 反复续跑或阻断全部工具。`PreToolUse` 的匹配范围只覆盖它负责限制的具体方法。

## 状态目录与保留期限

工具共享同一状态根。优先读取绝对路径 `AGORA_STATE_DIR`，否则使用 `XDG_STATE_HOME/agora`，默认是 `~/.local/state/agora`。相对路径配置报错。除外部工具自身的内部临时文件外，Agora 开发产物都归入下面的位置。

| 位置 | 内容与保留方式 |
| --- | --- |
| `tasks/<task-id>` | 基线、复盘、任务证据和回执。交付后保留结论及必要诊断，删除已核对无保留价值的工作草稿 |
| `runs/<kind>-<id>` | mock 或测试拥有的文稿副本、数据库和临时文件。成功结束即释放 |
| `sessions` | hook 实际观测的 session 绑定，不保存聊天正文 |
| `design` | 仍在使用的探索，每项说明当前负责人和是否已被正式实现取代 |
| `archive/<topic>` | 仍需保留的历史来源与归档清单，不当作当前运行入口 |

任务目录中的工作草稿、PR body 和一次性脚本不长期堆积。交付时把必要结论放到所属文档，`evidence` 只保留简短索引。日志、截图、数据库、逐条操作记录和可重建产物保存在受管状态目录或 CI artifacts。需要保留的资料记录原因和重新评估条件。不要为每条命令另建系统 `/tmp` 目录。

归档保留到来源可以重建、关联变更已完成且没有文档仍依赖它时，再由明确的清理任务复核。按时间自动删除不适用于测试文稿、基线或历史来源。

## 运行资源的创建者负责回收

mock 和测试通过[开发运行目录](../dev/runtime/README.md)分配资源。标记记录类型、创建进程、任务和状态。设置 `AGORA_TASK_ID=<task-id>` 可把运行归到本轮任务。

mock 正常停止或启动失败时，关闭 worker 和服务，再释放它自己创建的目录。要检查停止后的数据库，用 `--retain-run` 显式保留，并执行打印的清理命令。用户通过 `--file` 和 `--runtime` 指定的路径由用户管理，不进入自动删除。

`pnpm test` 和 `pnpm test:browser` 将子进程的临时目录、mock 和截图收在一次受管运行中。成功后释放，失败或中断时保留并打印清理命令。单独绕过 runner 执行测试时，不能声称完成了相同的目录隔离验收。

runner 对比运行前后的源码清单与摘要。测试修改了仓库文件，即使断言通过也要失败。测试进程退出后，仍有该运行创建的子进程时，终止所属进程组并将本次运行记为失败。它不处理其他运行的 PID。

浏览器可能另建进程组，不能只检查测试入口的进程组。测试进程的创建事件和启动身份要登记到本轮资源记录，关闭时核对身份再回收。测试夹具先回收进程，再删除身份记录和目录，避免失败断言让清理失去依据。

测试专用的[进程归属模块](../scripts/test-processes.mjs)通过 Node 创建事件和预加载登记子进程。身份来自 macOS 的进程启动时间或 Linux 的启动标识与进程时钟。独立进程组必须有仍匹配的所属成员，才可整组回收。身份不明时保留失败状态，不能猜测后终止其他进程。

这项检查在 macOS 和 Linux 验收。原生守护进程、主动移除归属环境的后代及无法观察的创建窗口不属于通用进程沙箱。需要这类后台能力时，先提供明确的创建与回收入口及验收，不能把它放到普通测试里并声称已自动回收。

运行 `pnpm clean:dev` 查看清单。完成排查后，使用输出中的精确目录名运行 `pnpm clean:dev --remove <name>`。自定义状态根必须带上输出的环境变量。清理命令拒绝活进程、未知标记、任意路径、通配符和符号链接，不按目录名猜测归属。

强制结束进程可能来不及运行清理。留下的受管标记供下次查看和回收。任务收尾要说明保留资源的原因与清理命令，不能直接写成“已清理”。

## 仓库与 CI 的边界

仓库保存源码、锁定配置、确定性的测试夹具和长期说明。`evidence` 保存索引，具体产物通过固定构建、提交或 CI artifact 定位。[仓库检查](../scripts/check-repository.py)拒绝未声明的根目录、运行数据库、日志及生成证据，并进入 `pnpm check`。

`node_modules` 是锁定依赖的本地缓存，`dist` 和 `coverage` 是可重建输出。这些目录不进入 Git。需要释放构建输出时运行 `pnpm clean:build`，依赖缓存由安装工具管理。不能把忽略规则当成存放任意临时资料的许可。

CI 使用 checkout 外的一处状态根，先安装锁定依赖，再运行同一个 `pnpm check`。它检查源码未被修改，失败诊断上传到有保留期限的 artifact，随后清理本次状态根。CI 的一次性宿主负责销毁作业环境。验收结果要区分本地检查、真实 CI 作业和真实 Codex hook 触发。

## 已知工具能力要成为后续选择

当前 GitHub 连接器创建 PR 已两次返回 403。该具体方法登记在[工具限制](../.codex/tool-policy.json)，后续使用本机已验证可用的 `gh`。读取 PR 的连接器能力继续按实际结果使用。

只有权限或连接发生明确变化、并有新的验证依据时，才重新评估限制。不要在每个任务重新尝试相同的失败，再把回退到 `gh` 当作新的发现。

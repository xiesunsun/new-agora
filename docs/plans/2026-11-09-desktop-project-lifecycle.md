## 设计与共享契约

- Markdown 的规范绝对路径决定项目身份；同一路径恢复原工作稿、批注和版本，新路径拥有独立状态。项目数据长期保存在状态根的 `projects` 下，不进入开发运行清理。
- 桌面插件在首次打开项目时启动打包后的正式服务子进程。MCP 连接结束、信号退出和父进程意外消失时，所属服务关闭；项目数据保留。服务进程不用 mock，也不依赖仓库内的依赖安装。
- 服务仍只负责一份稿件。插件通过现有 HTTP 契约路由到各项目，不导入服务业务实现。服务取得独占数据库锁后，在桌面入口允许新宿主会话绑定当前对话；执行未知的恢复门槛保持原状。
- 项目的活动对话归属由 MCP 父进程持有独占 SQLite 租约，并在进程内记录对话身份。子服务崩溃不释放对话归属；父进程结束后操作系统释放租约，后续连接才可接管。首次打开失败且未建立项目时释放新租约。
- 打开结果携带 `projectId`。面板读取、命令和唤醒都携带该身份；切换到另一项目不会重定向已打开的面板。领取接受显式 `projectId` 并在结果中返回它。执行编号在当前连接内关联原项目；重启后的提交与结束报告通过显式项目身份定位原服务，再由服务核对原执行编号，迟到提交不能落到当前新项目。
- 当前对话未打开的项目不能直接读取或领取；另一个仍活动的对话不能接管同一项目。没有路径时恢复当前对话上次打开的项目；从未打开时给出提供路径的提示。
- 保留显式 `AGORA_CONNECTION` 的外部服务模式用于既有联调与回归；默认安装使用插件拥有服务的模式。

## 文件归属与实施

由本轮主代理协调全部改动，避免与已接受的测试整理发生并行写入。评审代理只读，不修改文件。

1. **先建立回归并观察失败。** 新建 `tests/desktop-projects.test.mjs`，通过构建后的 MCP stdio 入口测试无外部连接时打开、路径隔离、旧面板身份、候选提交路由、宿主关闭后端口关闭、重开恢复、另一活动对话拒绝、未知执行恢复。扩充 `tests/desktop-host.test.mjs` 核对面板命令和通知带项目身份。使用受管 runner 验证资源回收。
2. **正式服务进程入口。** 新建 `apps/service/src/run.ts`，只接收文件和状态目录，启动正式服务、发送就绪 IPC，并在 IPC 断开、stdin 关闭或终止信号后关闭。`apps/service/src/server.ts` 与 `document.ts` 只增加桌面独占启动时重建对话绑定的选项，不改变显式服务的默认规则。
3. **桌面项目生命周期。** 在 `plugins/desktop/src` 增加 `connection.ts`（既有 HTTP 客户端）与 `projects.ts`（路径身份、持久化最近项目、服务启动和退出）。更新 `server.ts`，在默认模式按项目路由，保留外部服务模式，并在 MCP 关闭时回收全部所属子进程。
4. **面板与打包。** 更新 `host.ts` 传递项目身份。更新 `scripts/build.mjs` 打包独立服务与所需面板资产；更新 `.mcp.json` 的环境传递及插件版本。完整安装包不引用临时联调任务目录。
5. **验证并部署。** 运行 `pnpm check`；审阅关键并发、错误和回收路径；在持久本地市场安装当前构建，真实宿主用测试副本打开、生成和恢复。当前宿主不能动态加载新构建的部分明确列出，必要的宿主重载放到可验证构建准备好之后。

## 验收

- 在没有服务、没有 `AGORA_CONNECTION` 的环境中，`agora_open_document(path)` 成功，随后可领取并提交真实候选。
- 先打开 A，再打开 B。A 的面板仍只读取 A；A 的执行提交不改变 B；A 与 B 草稿、历史和磁盘内容独立。
- 关闭 MCP 后所有所属服务端口关闭。分别在子服务启动中和就绪后强制结束 MCP 父进程，检查子服务仍会退出。重新连接并打开 A 恢复草稿与审阅；被打断的执行仍为未知，不假定 Codex 已结束；携带原项目身份和执行编号可以报告实际结束。
- 活跃的另一对话不能读取、领取或接管 A。旧连接关闭后新对话可显式打开 A，得到同一份项目进度。
- 安装后的服务与插件都可脱离仓库 `dist` 和 `node_modules` 启动；日常入口不要求用户管理端口或终端。

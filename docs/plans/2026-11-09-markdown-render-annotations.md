# Markdown 渲染与选区批注修复

状态：已修复并安装 0.2.1；原测试聊天重载后的现场复核待完成。

## 基线与问题

沿用用户主目录，依赖已接受的 `codex/feat-desktop-project-lifecycle` 工作树；起点提交为 `56e27350bc878149f423461d4e67e1102277aedc`。任务 `2026-11-09-markdown-render-annotations` 已在仓库外保存当前未提交文件的清单和摘要。本轮分支为 `codex/fix-markdown-render-annotations`，不另建 worktree，也不改写测试聊天绑定的原文稿。

真实测试文稿包含普通列表、链接和加粗。当前 `supportsProse` 把这些结构都送进整篇 textarea。textarea 虽能生成原始文字锚点，但批注笔尖的位置仍依赖没有建立的正文 DOM 节点，因此入口被隐藏。已有测试验证原文编辑与快捷键的格式保真，没有验证此类文稿的正常呈现和点击批注。

## 修复范围

- 用成熟 CommonMark/GFM 解析器生成有源位置的语法树，默认呈现标题、列表、链接、行内格式、引用、代码与表格。用 DOM 节点构造输出，原始 HTML 显示为文字，危险 URL 不成为链接。
- 阅读与直接编辑模式由解析结果决定，不能继续以原来的正则识别语法。补验 setext 标题、分隔线、删除线和实体，避免仍被误判成普通文字。
- 渲染模块只持有正文到 DOM 的投影及 UTF-16 位置映射。批注仍引用服务中原始 Markdown 的准确切片，不从 HTML 反向序列化正文；重复文字、emoji、转义、实体和混合换行分别验证。
- 保留简单正文的现有直接编辑。结构化 Markdown 默认展示可选字批注的阅读视图，提供明确的“编辑原文／返回文稿”切换；原文编辑继续使用已验证的保真逻辑，并提供不依赖 DOM 行框的选区批注按钮。
- 不改任务、审阅选择和原文件写回的裁决；服务仍是唯一持久化写入方。原文稿只读验证，写回使用测试副本。

# Ink 界面与 mock 的接入边界

## 问题

墨间原型已确认正文、批注、行内审阅和历史的交互。其 notebook 同时保存业务状态和模拟原文件。正式服务已经负责真实文稿、待审文件和版本。直接复制 notebook 会产生两套业务规则。

## 选择

同一套面板继续通过 PanelTransport 接入浏览器和桌面宿主。服务是文稿、任务、审阅选择、写回与版本的唯一持久化写入方。面板保留尚未确认的输入及焦点、选区、滚动和展开状态。

优先保留原型的 DOM 结构与几何计算，将其转换为严格类型模块。小型控制器处理异步命令、输入保存和修订顺序。控制器不执行模拟改稿、不决定写回成功，也不保存第二份历史。

mock 使用独立配置与启动入口，运行真实服务并创建测试文稿副本。脚本执行器只替代 Codex。示例内容、确定性改稿和延迟在 mock 目录维护。需要模拟外部故障时，仅提取实际需要的服务依赖。

## 业务约束

- 生成冻结底稿和批注。服务生成并保存审阅单元，重开不重新分组。
- 所有建议选择完成后才可保存。未选择表示待选，不能隐式当成舍弃。保存入口比较实际预览与工作稿基点。全舍弃仍可保存已有的人类编辑，预览等于基点时不增加保存入口。
- 停止不能声称终止了外部 Codex。未知执行保留身份，迟到结果不能成为新一轮建议。重试需要结束证据。
- 历史采用只切换工作稿，不写原文件或新增版本。工作稿基点与最新磁盘版本分别记录。
- 写入核对只读取原操作证据。成功需原文件读回与目标一致，同一操作只能登记一个版本。
- 未识别的 Markdown 保留原文。显示与编辑不能因序列化丢失格式或换行。

## 取舍

React 重写可提供组件生命周期，但会同时改动经过验证的选区、组合输入和几何时序。本次优先保留这些行为。浏览器独立领域核心会增加一次额外拆分，本次复用现有服务与执行器。

Ink 是本次来源原型的代号。接入文档沿用了它，没有单独确定它是正式产品、模块或框架名称。当前实现按面板、编辑器和脚本执行器的职责命名；本文件及原迁移证据保留历史来源名称。

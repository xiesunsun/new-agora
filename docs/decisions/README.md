# 开发决策

## 在当前对话里生成一份待审稿

用户编辑或留批注后，主动点 **生成修改建议**。一次把当前工作稿和本轮意见交给原 Codex 对话。这样 Codex 能延续对话上下文，用户也能在生成前改口。按每条批注立即开始可以更早出结果，等首版之后再评估。

Codex 用原生工具改待审 Markdown。Agora 读回结果，和本轮底稿比较。这个分工保留文件编辑体验，也让原文件的写入集中在用户应用时。待审路径是工作约定。强制限制 Codex 的写入范围需要工具或运行环境的权限约束。

[批注与生成修改建议](../flows/annotate-and-sync.md) · [桌面接入](../../plugins/desktop/README.md)

## 一次应用，同时保存历史

用户可以在预览里反复调整选择。点 **保存** 后，Agora 写入目标、读回核对，再登记版本。写入和登记是后台两步，用户看到的是一个操作和明确结果。

先保存要写什么，才能在写入后程序中断时核对实际文件并补记版本。版本历史保存首次打开的原文，以及后来成功应用的正文。审阅差异比较底稿与待审稿，历史差异比较两个版本，分别回答 Codex 建议了什么和用户最终保存了什么。

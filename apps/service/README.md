# 本地服务

本地服务保存工作稿、批注、改稿结果、审阅选择和历史版本。首版只处理一份已绑定的文稿和同一份文稿的一轮在途生成。

1. 开始生成时保存一份固定底稿和当时的批注。核对领取对话和原路径绑定，给本轮分配单独的待审路径。
2. 只接收当前有效执行提交的待审稿。读取待审文件并保存提交时的正文，用底稿算出差异。重复提交返回原结果，迟到结果不能替换当前待审稿。
3. 用户应用时，根据保存的底稿和选择计算目标正文。直接应用人工编辑时，目标是已保存的工作稿。核对用户确认的内容和当前状态，再记录写入前的内容、目标正文和本次操作编号，供写入中断时核对。
4. 写后重新读取原文件。内容等于目标时，登记对应的正式版本并返回成功。同一操作只登记一次。若目标等于当前版本，沿用该版本编号。

重开后先查原操作。磁盘已等于目标时补记缺失的版本，避免重复写入。磁盘仍是写入前的内容时，确认原写入已结束，再决定是否按原目标继续。无法核对时保留待核对状态。确认原执行已结束前不重新分配同一项未知工作。详细场景见[写入中断](../../tests/README.md#a10)。

V1 保存首次打开时的原文件内容。后续版本保存应用时实际核对的正文。回执收缩、数据清理和缓存维护放在[后续验收](../../tests/README.md#a12)。

## Ink 的任务与工作稿

停止生成会撤销旧候选的发布权限。已领取执行结束未知时，保存编辑不能清除这项未知工作，重试、全新生成与历史采用均保持阻止。匹配执行的迟到提交或结束报告只提供结束证据。

历史采用切换工作稿基点，独立保留磁盘最新版本。采用后没有实际编辑，不能因全舍弃审阅而把旧版本写回。用户确认放弃审阅后可以切换历史，生成、批注输入、待核对写入和未知执行期间拒绝切换。

持久化使用有版本的记录。迁移保留原审阅范围、选择与写入回执，不为旧时间和未知请求修订发明值。写回前全部建议必须已选。已确认写回后，仅清理本轮提交且修订未变的已处理批注。

重新核对只读取原操作。原文件仍等于写入前正文时报告未写入，操作编号不能被另一项请求复用；内容无关时保留待核对。读回等于目标后，只登记一次正式版本。

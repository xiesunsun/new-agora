# Agora 验收场景

这些场景用于验证 [参考实现](../docs/archive/README.md)及后续新实现。编号沿用旧 `End-to-End-Acceptance.md`。A07 是同区冲突，A08 是位置漂移。阅读旧 P5 矩阵时按场景内容匹配，它交换了这两项标签。

参考实现使用 Node 22 及 `next/package.json` 声明的 pnpm。从旧仓库的 `next/` 执行：

```sh
pnpm install --frozen-lockfile
pnpm check
```

`pnpm check` 检查格式、导入边界、构建和自动化测试。浏览器使用参考实现的 `pnpm start`。真实宿主使用 [桌面接入](../plugins/desktop/README.md) 的安装和构建核对步骤。

每个场景用新的测试文档和隔离的运行目录。重启场景保留原 SQLite 和原文件。准备两个可区分的 Markdown 段落，并包含 BOM、CRLF 或 emoji 的精确文本样例。浏览器、受控 worker、打包产物和真实宿主分别记录。填写场景编号、入口、构建、故障点、实际结果和证据位置。既有记录见[历史证据](../evidence/README.md)。

## A01

**正常协作闭环。** 导入得到 V1，保存一处人类编辑，提交两条批注并冻结审阅。让执行者在同一路径编辑并结算。接受第一项，拒绝第二项，确认版本，再对齐。检查界面投影、持久决定及原文件。接受后仍为 V1，确认后仅新增 V2，最终文件与 V2 正文相同。参考 `reviews.test.ts`、`desktop.test.ts`。

## A02

**重复请求。** 对正文保存、批注、决定与确认丢弃响应，使用相同调用范围、请求 ID 和参数重放。每次只产生一次持久效果，同 ID 换参数拒绝。新 ID 发送相同批注文本可产生新的批注。参考 `documents.test.ts`、`work.test.ts`、`reviews.test.ts`。

## A03

**宿主忙碌、重复唤醒和并发领取。** 宿主忙时提交两项任务，重复唤醒并并发领取。核对受理消息时任务仍排队，只有一个执行获得当前槽位。已结算后送达的旧唤醒不产生编辑。用真实宿主核对当前对话，另测外来对话拒绝。参考 `work.test.ts`、`desktop.test.ts`。

## A04

**编辑草稿、断线和重连。** 保存前断线并继续输入，再重开。检查本机输入存在。随后模拟旧保存请求成功但回执迟到，同时加入更新输入。旧回执只结算原请求；基底冲突时保留两份内容并停下。参考 `controller.test.ts`、`draft.test.ts`。

## A05

**接受修改时丢响应。** 让决定提交成功，但丢弃响应并重开。检查原请求身份和已作决定可核对，工作正文只变一次。再确认版本，检查只新增一个版本。另测较晚作出的决定不被旧响应撤回。参考 `reviews.test.ts`、`maintenance.test.ts`。

## A06

**明确失败、部分结果与重试。** 在开始前和部分文件写入后分别中断执行。已登记候选保留。失联时保持待核对与槽位。只有明确停止并核对文件后才结算失败，用户明确重试产生一个队尾尝试。参考 `work.test.ts`、`reviews.test.ts`、`desktop.test.ts`。

## A07

**用户与 Agent 修改同一位置。** 让两方分别修改同一原句。比较用户工作正文、文件和候选。冲突时保留双方内容，未经决定的候选不覆盖工作正文。另测不相交的修改可保留。参考 `work.test.ts`、`reviews.test.ts`。

## A08

**批注与修改位置漂移。** 测试目标前插入、边界插入、重复文本、删除选区和 emoji。界面位置随正文更新，原始目标与 Change 范围不变。归属不明确时提示重新定位或冲突。参考 `work.test.ts`、`manuscript.test.ts`。

## A09

**重启与审阅恢复。** 分别在排队、执行、准备审阅和部分决定后重启。旧执行结果未知时保留原上下文与槽位，已作决定与审阅依据继续存在。分别验证服务、文件桥和真实桌面应用重开。参考 `work.test.ts`、`reviews.test.ts`、`desktop.test.ts`。

## A10

**写入与文件回执故障。** 分别在计划提交前、实际写入前、写入后未登记回执及回执已提交后中断。文件等于目标时补原回执，偏离原文和目标时停下并保留实际内容。旧计划的回执不能结算更新的工作正文。参考 `work.test.ts`、`desktop.test.ts`、`maintenance.test.ts`。

## A11

**历史预览与恢复。** 让旧版本预览响应迟于新选择返回，再返回工作正文并明确恢复历史内容。预览保持当前正文和版本指针。恢复不同正文时创建新版本，记录恢复来源。含待决定修改或未结算写入时验证恢复受阻。参考 `documents.test.ts`、`controller.test.ts`、`reviews.test.ts`。

## A12

**清理与恢复依据。** 保留多份版本和一项未结算计划，运行维护并重建缓存。正式正文、检查点和活动恢复证据仍可读取。已收缩的同请求保留去重效果。参考实现覆盖引用保护、详情收缩和可重建缓存。可选业务历史裁剪是旧设计项。参考 `maintenance.test.ts`。

所有测试文件路径相对参考实现的 `next/tests/`。整套验证还覆盖事务失败无部分效果、调用者范围隔离、旧执行无法结束后续工作，以及缺失文件与空 Markdown 的区别。
